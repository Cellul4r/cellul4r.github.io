## ปัญหาแบบตัดสินใจและเวลาในการทำงาน

ก่อนที่เราจะเข้าไปในประเภทของปัญหาที่เป็น P หรือ NP กัน เราจะโฟกัสกับความหมายของปัญหาการตัดสินใจหรือ Deicision Problem ก่อนว่ามันคืออะไร?
Decision Problem คือปัญหาที่เราต้องตอบว่า "yes" or "no" แค่นั้นเลย ใช่ แค่นี้แหละ นี่คือความหมายของปัญหานี้ ถ้าจะให้ยกตัวอย่างก็
เหมือนกับ เราถามว่า ตอนนี้ที่บ้านของคุณมีคนทั้งหมด 5 คนใช่หรือไม่? ซึ่่งเราก็จะตอบตาม fact โดยการนับจำนวนคนว่ามี ครบ 5 คนจริงไหมนั่นเอง
ซึ่งปัญหาเหล่านี้ก็จะมี Algorithm ที่เข้ามาช่วยเรา "แก้ปัญหา หาคำตอบของคำถาม" หรือ "ตรวจสอบคำตอบว่าถูกต้อง หรือไม่" ซึ่งเราก็สามารถแบ่ง Algorithm พวกนี้เป็น 2
กลุ่มได้เช่นเดียวกัน ซึ่งต่อไปเราจะมาแบ่งปัญหา Decision พวกนี้เป็น P หรือ NP ออกมานั่นเองง 
แล้วก็แบ่งเป็น 2 กลุ่ม Polynomial-time กับ Exponential-time Algorithm พร้อมยกตัวอย่าง รูปภาพต่างๆ ให้เข้าใจง่าย
## P คืออะไร?

เขียนคำอธิบายและตัวอย่างโจทย์แบบตัดสินใจที่มีอัลกอริทึมแก้ได้ในเวลาพหุนาม
ปัญหา Class P คือ ปัญหาที่สามารถ"หาคำตอบ" ของคำถามได้ด้วย Polynomial-time Algorithm ถ้าเราดูจากคำถามตะกี๊ที่เราถามว่า
ตอนนี้บ้านของคุณมีคนทั้งหมด 5 คนใช่หรือไม่ สังเกตว่าเรานั่งนับทีละคนในบ้านเลยว่ามีกี่คน 1,2,3,4,...5 คน! แล้วเราก็ตอบว่าใช่หรือไม่ (ตอบใช่) ถ้ามี 4 คน ก็นับ 4 คน (ตอบไม่)
ถ้ามี 6 คน เรานับ 6 คน (ตอบไม่)
7 คน ก็นับ 7 (ตอบไม่) ไปเรื่อยๆ ดังนั้น Algorithm วิเคราะห์ได้ว่าเราใช้เวลาในการนับตามจำนวนคนที่มีในบ้านซึ่งเป็น Polynomial-time O(N)
สำหรับปัญหาอื่นเช่น Minimum Spanning Tree ที่เราจะถามด้วย Deicision Problem กราฟ G กราฟหนึ่งมี Spanning Tree ที่มีค่าผลรวมของเส้น edge weight รวมกันไม่เกิน K
หรือไม่? ซึ่งสำหรับปัญหานี้ก็มีคนพิสูจน์หา Algorithm ในการหา ผลรวม weight ที่เป็น minimum อยู่แล้วก็คือ Kruskal's Algorithm และ Prim's Algorithm นั่นเอง ซึ่งสามารถรัน Algorithm ที่ภายใน Polynomial-time ได้นั่นเอง พร้อมกับภาพอนิเมชั่นตัวอย่าง

## NP คืออะไร?

อธิบายว่าเมื่อคำตอบเป็น “ใช่” เราสามารถตรวจสอบหลักฐานที่มีขนาดพหุนามได้ในเวลาพหุนามอย่างไร
ต่อไปเป็นปัญหา Class NP คือ ปัญหา Decision Problem ที่เราสามารถ "ตรวจสอบคำตอบว่าถูกต้อง" (Verify) หรือไม่
ใน เวลา Polynomial-Time Algorithm ซึ่งขอโน้ตไว้ว่าปัญหาที่อาจจะมีวิธีการแก้ปัญหา หาคำตอบได้ Polynomial-Time Algorithm หรือไม่มีก็ได้ หรือ ยังหาไม่เจอก็ได้นะ
ยกตัวอย่างปัญหาที่เห็นภาพเข้าใจง่าย ตัวอย่างเช่น ปัญหา N-Queen ที่เรามีกระดานขนาด 5x5 (แล้วก็มี animation รูปภาพทำยังไงก็ได้ให้เข้าใจง่าย) และเราต้องหาคำตอบว่ามีวิธีวาง หมากรุก Queen 5 ตัว โดยที่
ไม่มี queen ตัวไหนอยู่ในคอลัมน์หรือแถวเดียวกันเลย หรือไม่? ซึ่งวิธีแก้ปกติ เราก็จะใช้ backtracking loop recursion หาวิธีการจัดวางที่ถูกต้อง และตอบคำถามได้ โดยAlgorithm ทั่วไปจะใช้เวลา O(N!) ตามขนาดของกระดาน NxN ซึ่งเป็น exponential-time algorithm 
แต่ถ้าเรามีคำตอบอยู่แล้วล่ะ? เราก็จะสามารถทวนเช็คได้เลยว่า ในแต่ละแถวและแต่ละคอลัมน์ มี Queen วางบนกระดานเกิน 1 ตัวไหม? ซึ่งสังเกตว่าเราแค่ไล่ทีละแถว และทีละคอลัมน์ และนับจำนวนของ Queen ซึ่งใช้เวลาภายใน O() .... Algorithm (https://www.geeksforgeeks.org/dsa/n-queen-problem-backtracking-3/)
พร้อมกับ นี่เป็น Pseducode คร่าวๆสำหรับการ VerifyQueenSolution(N, Solution) โดยที่ N คือขนาดของกระดาน, Solution คือคำตอบว่าเราวาง Queen ที่แถวไหน คอลัมน์ไหนบ้าง
แล้วก็โชว์วิธีการเขียนไปเลย 
## P กับ NP เกี่ยวข้องกันไหม?

อธิบายว่า P เป็นส่วนหนึ่งของ NP และคำถามว่า P เท่ากับ NP หรือไม่ยังเป็นปัญหาที่ยังไม่มีคำตอบ
ถ้าเราสังเกตปัญหา P คือปัญหาที่เราสามารถหาคำตอบได้ในเวลา Polynomial-time Algorithm ในเมื่อเราสามารถหาคำตอบที่ถูกต้องได้อยู่แล้ว นั่นคือเราก็ตรวจสอบได้ในเวลา Polynomial-time เหมือนกันว่าคำตอบมันถูกต้องแน่นนอน
นั่นแสดงว่า ปัญหา P ก็คือปัญหา NP นั่นเอง!!!! (ไม่แน่ใจว่าสามารถโชว์คำถามเกี่ยวกับ P=NP? , P!= NP ใน section นี้ได้เลยไหมถ้าได้ ก็อธิบายมาตรงนี้ได้เลย)
โดยเราจะสามารถแสดงเป็นแผนภาพที่ P อยู่ในปัญหา Class NP ได้นั่นเอง (Math symbol P is subset of NP)

## Polynomial-Time Reduction
ก่อนที่เราจะลงลึกเกี่ยวกับปัญหา NP-Complete เราจะต้องทำความเข้าใจเกี่ยวกับการลดรูปปัญหากันก่อน ซึ่งถ้าอธิบายให้เข้าใจง่ายๆ คือเราหาวิธีการลดรูป
จากปัญหาหนึ่งๆ (A) ไปเป็นอีกปัญหาอีกแบบหนึ่ง (B) (ทั้งสองเป็น Decision Problem) โดยในการแปลงนี้ใช้เวลาภายใน Polynomial-time เขียนได้ในรูปแบบว่า `A<=pB`
แสดงแผนภาพเกี่ยวกับการลดรูปปัญหานี้ให้เข้าใจง่าย โดยแทนที่เราจะใช้ Algorithm ในการแก้ปัญหา A, เราจะใช้ Algorithm ในการแก้ปัญหา B แทน และให้ B ตอบแทนว่า Yes หรือ no
โดยเนื่องจากเราลดรูปปัญหามาแล้ว จะหมายความว่าถ้า B ตอบ Yes -> A ก็ตอบ Yes, B ตอบ No -> A ก็ตอบ No เหมือนกัน 
นอกจากนี้มันจะมีเรื่องความยากของปัญหา 2 ปัญหานี้อยู่ โดยจากที่เราลดรูปปัญหาจาก A ไป B ได้นั้นจะหมายความว่า ปัญหา A ไม่ได้ยากไปกว่าปัญหา B หรือ ปัญหา B ไม่ได้ง่ายกว่าปัญหา B
งง งงใช่ไหม ลองดูภาพประกอบ (อธิบายตรงนี้ให้เข้าใจง่าย)
ยกตัวอย่างการลดรูปปัญหานี้ให้เข้ากับชีวิตประจำวัน
## ต่อไปในตอนที่ 2 NP-Hard และ NP-Complete
เกริ่นเรื่อง NP-hard และ NP-complete ซึ่งจะอธิบายวิธีพิสูจน์ในตอนถัดไป
สำหรับในตอนต่อไป เราจะนำความเข้าใจเกี่ยวกับปัญหา P และ NP พร้อมทั้งการ ลดรูปปัญหาเนี่ยแหละ ไปเรียนรู้สิ่งที่คิดว่ายากๆ
แต่เราก็อาจจะไม่ได้ยากขนาดนั้น!? ไหมนะ ไม่รู้ อิอิ ซึ่งเราก็จะพิสูจน์เกี่ยวกับ ปัญหา NP-Complete ซึ่งเป็นปัญหาที่ยากที่สุดใน NP (จริงป่าววะ)
และ NP-Hard ซึ่งเป็นปัญหาที่ยากมากๆ โคตรยาก ยากอย่างน้อยหรือมากกว่าปัญหา NP และไม่จำเป็นต้องเป็นปัญหา Decision Problem ด้วยซ้ำ?
